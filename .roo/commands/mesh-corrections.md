Context: You are working inside a Python-based devcontainer without access to external 3D software (like Blender). Your task is to algorithmically analyze and fix 3D models in .gltf or .glb format for the Bevy Game Engine (v0.14) to prevent rendering crashes (invisible meshes) and incorrect collision shapes.

Implementation Details: Use Python libraries such as trimesh, pygltflib, or scipy to manipulate the models as data structures.

Execute the following steps programmatically for each model file:
1. Geometry Analysis & "All Transforms" (Bounding Box & Collision Shapes)

    Problem: Models often have unapplied scales, rotations, or translations in their scene hierarchy. This leads to incorrect bounding box and collision shape calculations in the game loop.

    Action: Use trimesh to bake the global transformation matrix directly into the vertex coordinates (vertices) of the mesh. Afterward, clear the hierarchical transformations by resetting the scale in the node tree strictly to [1.0, 1.0, 1.0], and setting rotation and location to zero.

    Goal: Calculate the exact Axis-Aligned Bounding Box (AABB) based on these cleaned, absolute vertices, and generate the coordinates required for the Bevy physics/collision shapes.

2. Texture Transcoding (JPEG to PNG)

    Problem: Bevy 0.14 crashes when parsing certain compressed JPEG formats (e.g., CMYK color spaces or progressive JPEGs) generated by AI tools, causing the entire mesh to render invisible.

    Action: Extract the embedded image data from the glTF buffer (or follow the URIs). Use the Python library Pillow (PIL) to open the JPEGs, convert them to RGB mode if necessary, and re-embed them into the glTF buffer as standard-compliant PNG bytes. Update the corresponding mimeType fields in the glTF JSON to "image/png".

3. PBR Material Correction (Metallic/Roughness)

    Problem: Automatically generated AI materials often set both metallicFactor and roughnessFactor rigidly to 1.0. This can cause broken light calculations in Bevy, resulting in a "black-hole" or completely transparent effect.

    Action: Locate materials[].pbrMetallicRoughness in the glTF JSON. Set metallicFactor to 0.0 by default (unless the asset is explicitly metallic) and lower the roughnessFactor to a moderate value (e.g., 0.5 or 0.6) if no roughness map is bound, ensuring proper PBR shading.

4. Tangent Generation for the Normal Shader

    Problem: The material contains a normalTexture, but the mesh accessors lack the required TANGENT attributes. Bevy 0.14 refuses to render the object entirely if a normal map is present without tangent data.

    Action: Use trimesh.geometry.triangle_tangents (or a similar mathematical algorithm) to calculate the tangent vectors based on the vertices, normals, and UV coordinates. Append this data as a new accessor and link it within the mesh attributes block: "attributes": { "TANGENT": <accessor_index> }.
